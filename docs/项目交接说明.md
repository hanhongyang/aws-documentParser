## 一、项目简介

### 项目名称

AWS PaaS 附件自动解析插件（`com.actionsoft.apps.attachment.parser`）

### 项目目标

在炎黄低代码平台（AWS PaaS 7.1.GA）上，实现附件上传后自动解析票据内容、识别费用类型、提取结构化字段、回填报销明细行，并提供附件在线预览能力。

### 当前实现能力

| 能力 | 状态 | 说明 |
|------|------|------|
| PDF 解析 | ✅ | 基于 PDFBox 2.0.36 |
| Word 解析 | ✅ | 基于 POI 5.4.1 XWPF |
| Excel 解析 | ✅ | 基于 POI 5.4.1 XSSF |
| TXT 解析 | ✅ | UTF-8/GBK 自动检测 |
| 铁路电子客票识别 | ✅ | 17 个字段提取 |
| 增值税电子发票识别 | ✅ | 15 个字段提取 |
| 费用类型自动分类 | ✅ | 10 种费用类型 |
| 子表自动新增 | ✅ | grid.addData() |
| 字段自动回填 | ✅ | 含 displayValue |
| 附件在线预览 | ✅ | onlinedoc_filepreview |

### 应用场景

- 差旅报销：自动解析火车票、飞机票、住宿发票
- 办公报销：自动解析增值税电子发票、餐饮发票
- 车辆费用：自动解析加油票、停车票、高速通行费

### 2. ASLP 入口 — ParseAttachmentASLP.java

**路径**：`aslp/ParseAttachmentASLP.java`（277 行）

#### 接口实现

```java
public class ParseAttachmentASLP implements ASLP {
    public ResponseObject call(Map<String, Object> params) { ... }
}
```

#### 输入参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `fileId` | String | AWS_FORM_FILE 表主键 UUID |

params 中还包含平台自动注入的 `sid`（会话 ID）和 `caller`（调用方 AppId）。

#### 执行流程

```
call(params)
  ├─ 1. 解析文件: PARSER_SERVICE.parse(fileId)
  │     ├─ SDK.getBOAPI().getFile(fileId) → byte[]
  │     ├─ 遍历 registry.getParsers(): supports(bytes) → 首个匹配
  │     └─ → ParseResult(text, type, size)
  │
  ├─ 2. 提取信息: EXTRACTOR_SERVICE.extract(parseResult)
  │     ├─ 遍历 registry.getExtractors(): supports(parseResult)
  │     │     ├─ 跳过 UnknownExtractor（instanceof 检查）
  │     │     ├─ RailwayInvoiceExtractor.supports() → "铁路电子客票"/关键字 ≥2
  │     │     └─ VatInvoiceExtractor.supports()      → 关键字 ≥1
  │     ├─ 首个匹配 → extractor.extract()
  │     ├─ 无匹配   → registry.getFallback().extract()
  │     └─ → ExtractResult(documentType, invoiceType, fields)
  │
  ├─ 3. 费用分类: BillTypeDetector.detect(text) → BILL_TYPE
  │              BillTypeDetector.detectExpenseType(billType) → EXPENSE_TYPE
  │
  ├─ 4. 附件信息: FormFileDao.queryById(fileId) → FormFile
  │              buildFileInfo(formFile) → FILE_INFO
  │
  ├─ 5. 预览 URL: buildViewUrl(formFile) → VIEW_URL
  │
  └─ 6. 返回: { success: true, data: { ... } }
```

### 3. Parser 体系

#### Parser 接口

```java
public interface Parser {
    String getType();                    // 文件类型标识
    boolean supports(byte[] bytes);      // 基于 magic bytes 判断
    ParseResult parse(byte[] bytes, String fileId);  // 执行解析
}
```

#### 已注册 Parser（Plugins.java）

| Parser | getType() | supports 逻辑 | 解析库 | 状态 |
|--------|-----------|-------------|--------|------|
| PdfParser | `pdf` | `0x25 0x50 0x44 0x46` (%PDF) | PDFBox 2.0.36 | ✅ |
| WordParser | `docx` | ZIP + 含 `word/` | POI 5.4.1 XWPF | ✅ |
| ExcelParser | `xlsx` | ZIP + 含 `xl/` | POI 5.4.1 XSSF | ✅ |
| TxtParser | `txt` | 4000 字节内无 0x00 | 纯 Java String | ✅ |
| ImageParser | `image` | JPEG(FF D8 FF) / PNG(89 50 4E 47) | 无（返回 unsupported） | ⏳ |
| UnknownParser | `unknown` | 永远 true（兜底） | 无 | ✅ |

#### ParserRegistry

```
单例模式，register() 注册顺序决定遍历优先级：
  PdfParser → WordParser → ExcelParser → TxtParser → ImageParser
  兜底: UnknownParser（不在遍历列表中，通过 getFallback() 获取）
```

### 4. Extractor 体系

#### Extractor 接口

```java
public interface Extractor {
    boolean supports(ParseResult parseResult);   // 特征关键词判定
    ExtractResult extract(ParseResult parseResult); // 提取结构化字段
}
```

#### 已注册 Extractor（Plugins.java）

| Extractor | supports 规则 | 提取字段数 | 状态 |
|-----------|-------------|-----------|------|
| RailwayInvoiceExtractor | "铁路电子客票" 或 ≥2 个关键词 | 17 个 | ✅ |
| UnknownExtractor | 永远 true（兜底） | 0 个 | ✅ |

#### AbstractRegexExtractor

所有正则提取器的基类，提供：
- `findFirst(regex, text)` — 正则捕获组匹配
- `normalizeMoney(text)` — 金额标准化
- `normalizeDate(text)` — 日期标准化
- `fullWidthToHalf(text)` — 全角转半角
- `preprocess(text)` — 文本预处理流水线

#### ExtractorRegistry

```java
单例模式:
  extractors = [RailwayInvoiceExtractor]  // Plugins 手动注册
  fallback   = UnknownExtractor           // 始终存在
```

> **注意**：`VatInvoiceExtractor` 在源码中存在但 Plugins.java 未手动注册。它通过 `ExtractorAutoScanner` 自动扫描 jar 中的 class 文件加载到 extractors 列表。`DocumentExtractorService` 主循环通过 `instanceof UnknownExtractor` 跳过兜底提取器，确保 UnknownExtractor 仅在无其它匹配时生效。

#### RailwayInvoiceExtractor（577 行）

识别关键词：`铁路电子客票`、`12306`、`电子客票号`、`车次`、`乘车日期`

提取 17 个字段（每个字段 2-4 个正则 Pattern，从精确到模糊逐级退化）：

| 字段 | Pattern 数量 | 兜底策略 |
|------|------------|---------|
| INVOICE_NO | 3 | 20/12/10 位纯数字 |
| INVOICE_DATE | 4 | 裸日期 YYYY-MM-DD |
| AMOUNT | 4 | 含"元"的金额格式 |
| BUYER_NAME | 3 | 紧邻税号前的长中文 |
| BUYER_TAX_NO | 3 | 孤立 18 位数字字母 |
| PASSENGER_NAME | 4 | 身份证号附近 30 字符 |
| PASSENGER_ID_NO | 3 | 脱敏格式兜底 |
| DEPARTURE_STATION | 5 | "站-站" 格式 |
| ARRIVAL_STATION | 5 | 同上 |
| TRAIN_NO | 4 | 无词边界兜底 |
| SEAT_TYPE | 3 | 关键词 + 等级格式 |
| SEAT_NO | 3 | 中文"排/座"格式 |
| BOARDING_TIME | 3 | 中文时间"点/分" |
| CARRIAGE_NO | 4 | 无"厢"格式"03车" |
| TICKET_NO | 4 | 纯数字长编号 |

特殊优化：`extractTrainCombo()` 一次匹配提取"开车时间+车厢号+座位号"组合（`09:29开 03车07A号`）。

#### VatInvoiceExtractor（194 行）

识别关键词：`电子发票`、`增值税电子`、`价税合计`、`销售方`、`购买方`

阈值：≥1（从 ≥2 降低以适应 PDF 排版导致的换行拆分问题）。

提取 15 个字段：INVOICE_NO、INVOICE_DATE、SELLER_NAME、SELLER_TAX_NO、BUYER_NAME、BUYER_TAX_NO、AMOUNT、TAX_AMOUNT、TOTAL_AMOUNT、ITEM_NAME、REMARK、ISSUER_NAME 等。

**不设置 EXPENSE_TYPE**（架构规则：费用分类由 BillTypeDetector 统一负责）。

### 5. BillTypeDetector

#### 作用

根据 PDF 解析文本识别费用类型（BILL_TYPE）和费用大类（EXPENSE_TYPE）。

#### 架构规则

- **Extractor 职责**：票据事实字段、DOCUMENT_CATEGORY、INVOICE_TYPE
- **BillTypeDetector 职责**：业务费用分类 — BILL_TYPE + EXPENSE_TYPE 统一来源
- **禁止 Extractor 设置 EXPENSE_TYPE**

#### 设计

配置驱动：启动时尝试加载 `classpath:config/bill-type-rules.json`（fastjson 解析），失败则使用 `hardcodedRules()` 兜底。当前部署环境无 JSON 配置文件，使用硬编码规则。

#### 当前 10 条规则

| 优先级 | BILL_TYPE | EXPENSE_TYPE | 关键词数 |
|--------|-----------|-------------|---------|
| 1 | 火车票 | 交通费 | 17 |
| 2 | 飞机票 | 交通费 | 9 |
| 3 | 出租车费 | 交通费 | 5 |
| 4 | 网约车费 | 交通费 | 10 |
| 5 | 加油费 | 车辆费用 | 8 |
| 6 | 住宿费 | 住宿费 | 9 |
| 7 | 餐饮费 | 餐饮费 | 9 |
| 8 | 停车费 | 车辆费用 | 3 |
| 9 | 高速通行费 | 车辆费用 | 5 |
| 10 | 租车费 | 交通费 | 3 |
| 兜底 | 其它费用 | 其他费用 | — |

#### 关键方法

```java
BillTypeDetector.detect(text)              → "火车票" / "加油费" / ...
BillTypeDetector.detectExpenseType(type)   → "交通费" / "车辆费用" / ...
BillTypeDetector.isConfigLoaded()          → 是否从 JSON 加载成功
BillTypeDetector.getRules()                → 当前生效的全部规则
```

### 7. VIEW_URL 生成

#### 方法

```java
private String buildViewUrl(FormFile formFile)
```

#### 生成格式

```
/r/w?cmd=com.actionsoft.apps.addons.onlinedoc_filepreview
  &appId={formFile.getAppId()}
  &fileNameOriginal={URLEncode(文件名)}
  &sourceFileName={URLEncode(文件名)}
  &sourceGroupValue={formFile.getId()}
  &sourceFileValue={formFile.getBoItemName()}
  &sourceRepositoryName=!form-ui-file-
  &sourceAppId={formFile.getAppId()}
  &isShowDefaultToolbar=true
  &isCopy=true&isPrint=false&isDownload=true
  &isEncrypt=true&isShowBackbtn=false
  &isPDFCovertPNG=0&isDecode=true
  &bucketFolder=&msaSvcId=awspaas
```

#### 参数来源

| 参数 | 来源 | 说明 |
|------|------|------|
| appId / sourceAppId | `formFile.getAppId()` | 附件所属应用 |
| sourceGroupValue | `formFile.getId()` | 文件 UUID |
| sourceFileValue | `formFile.getBoItemName()` | BO 字段名（如 "FILE"） |
| sourceRepositoryName | 固定值 `!form-ui-file-` | 平台表单附件仓库 |
| fileNameOriginal / sourceFileName | `formFile.getFileName()` URL 编码 | 附件文件名 |
| 其余 | 固定值 | onlinedoc 服务渲染参数 |

#### 设计原因

不使用 `/r/uf`（平台文件下载 URL）是因为：
- `/r/uf` 在新窗口中缺少 session cookie → 返回 403
- `onlinedoc_filepreview` 是平台官方的在线预览服务，支持 PDF/Office/图片
- URL 参数完全复刻平台 `CLIENT_UI_FILE_PREVIEW_FILE` 的成功日志格式

## 五、前端详细设计

### 1. 文件上传触发

用户上传主表附件，通过**文件保存后事件**触发解析。

获取：
```
eventContext.file.id
```

作为 ASLP 调用的 `fileId`。

### 2. 调用 ASLP

```javascript
POST /r/jd
参数:
  cmd:           API_CALL_ASLP
  aslp:          aslp://com.actionsoft.apps.attachment.parser/parseAttachment
  authentication: formApi.api.getSid()
  params:        { fileId: fileId }
```

### 3. ASLP 返回

从 `res.data.data` 获取解析结果，包含：

```
INVOICE_DATE      开票日期
AMOUNT            金额
PASSENGER_NAME    乘车人
DEPARTURE_STATION 出发站
ARRIVAL_STATION   到达站
FILE_INFO         附件完整信息
VIEW_URL          在线预览 URL
VIEW_NAME         附件文件名
```

### 4. 自动新增子表

使用平台 API 新增子表行：

```javascript
formApi.grids["BO_xxx"].addData(function(context) {
    context.rowData.DATE           = data.INVOICE_DATE;
    context.rowData.PROJECT        = data.EXPENSE_TYPE;
    context.rowData.REASON         = "";
    context.rowData.LOCATION       = data.DEPARTURE_STATION + "-" + data.ARRIVAL_STATION;
    context.rowData.AMOUNT         = data.AMOUNT;
    context.rowData.PARTICIPANTS   = data.PASSENGER_NAME;
    context.rowData.ATTACHMENT_ID  = data.FILE_INFO.id;
    context.rowData.VIEW_NAME      = data.VIEW_NAME;
    context.rowData.VIEW_URL       = data.VIEW_URL;
});
```

### 5. displayValue

低代码平台字段显示需同步 `$dataExtend`，否则单元格不显示值：

```javascript
context.rowData.$dataExtend.DATE.displayValue          = data.INVOICE_DATE;
context.rowData.$dataExtend.PROJECT.displayValue       = data.EXPENSE_TYPE;
context.rowData.$dataExtend.LOCATION.displayValue      = loc;
context.rowData.$dataExtend.AMOUNT.displayValue        = data.AMOUNT;
context.rowData.$dataExtend.PARTICIPANTS.displayValue  = data.PASSENGER_NAME;
context.rowData.$dataExtend.ATTACHMENT_ID.displayValue = data.FILE_INFO.fileName;
context.rowData.$dataExtend.VIEW_NAME.displayValue     = data.VIEW_NAME;
context.rowData.$dataExtend.VIEW_URL.displayValue      = data.VIEW_URL;
```

### 6. 附件预览方案

**不使用子表附件字段**。原因：附件组件内部 `fileList` 结构依赖 `CLIENT_UI_FILE_DATA` 服务端返回，无法从 JS 侧稳定构造。

**采用方案**：
- 子表配置 `VIEW_URL` 隐藏字段 + 按钮快捷取值 `$[VIEW_URL]`
- 用户点击按钮 → `window.open(VIEW_URL)`
- 打开炎黄官方 onlinedoc_filepreview 在线预览

**支持预览格式**：PDF / Office / 图片。

### 7. 已验证流程

```
上传火车票 PDF
  → 文件保存后事件触发
    → POST /r/jd?cmd=API_CALL_ASLP&aslp=parseAttachment
      → ParseAttachmentASLP 解析 + RailwayInvoiceExtractor 提取
        → 返回 17 个字段 + FILE_INFO + VIEW_URL
          → grid.addData() 自动新增子表
            → 用户点击「查看票据」按钮
              → window.open(VIEW_URL)
                → onlinedoc 打开 PDF 预览 ✅
```
